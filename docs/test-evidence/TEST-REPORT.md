## 3. 发现的问题与修复（BUG#1–#8）

### BUG#1 文件版本历史不可用（列表为空、还原无效、覆盖不存档）
- **现象**：记事本覆盖保存后版本历史为空；版本列表/还原点击无反应。
- **根因**（两层）：
  1. 后端 `fs.go` 的 `WriteText`（文本编辑器保存路径）覆盖前未调用 `fscore.SaveVersion` 归档旧版本 —— 上传/Office 覆盖路径有，唯独文本编辑路径漏了；
  2. 前端 `Explorer.vue` 对 `fsApi.fileVersions`/`fileVersionRestore` 的返回值二次解包（`res.code === 0 && res.data`），而 http.ts 已统一解包 data 并在失败时抛错 → 列表恒为空数组、还原分支永不执行。
- **修复**：`fs.go` WriteText 在覆盖前对本地策略 `SaveVersion`；`Explorer.vue` 两处改为直接取解包后的 data、resolve 即成功。
- **验证**：连续覆盖保存 3 次 → 版本历史列出 3 个版本；还原到 v1 后文件内容回退、列表刷新；版本下载字节正确。✅

### BUG#2 多标签页会话互相顶替
- **现象**：标签页 A 以 admin 登录，标签页 B 游客登录后，A 被踢回登录页。
- **根因**：令牌存 `localStorage`（同源共享），B 的 `cp_token` 覆盖 A；`notify.ts`/`session.ts` 也各自直读 localStorage。
- **修复**：`http.ts` 令牌改存 `sessionStorage`（按标签页隔离），`notify.ts`/`session.ts` 统一走 `getToken()/clearToken()`。
- **验证**：A(admin) 与 B(游客) 并排操作互不影响，各自数据视图正确。✅

### BUG#3 分享下载次数限制不生效，且 404 也消耗次数
- **现象**：设 2 次下载上限后仍可无限下载；请求不存在路径（404）也扣次数。
- **根因**：`share.go` `loadShare` 未校验 `RemainDownloads == 0`；`Download` 在文件存在性检查**之前**扣减计数。
- **修复**：`loadShare` 增加 `RemainDownloads == 0 → 「下载次数已用完」`；计数移到 `shareTarget` 确认存在之后。
- **验证**：上限 2 → 前两次成功，第三次 403「下载次数已用完」；故意 404 后计数不变。✅

### BUG#4 管理端本地策略「测通」显示「已用 -」
- **现象**：本地存储策略点「测通」弹「连通正常！已用 -」。
- **根因**：本地策略无配额概念（used/total 为 0），前端无条件拼配额文案。
- **修复**：`AdminConsole.vue` checkPolicy：无配额信息时直接展示 msg（「本地存储」）。
- **验证**：本地策略测通显示「连通正常！本地存储」；云盘策略仍显示「已用 x / 总量 y」。✅

### BUG#5 Windows 10.0.28000（Insider）环境 ConPTY 失效导致终端不可用
- **现象**：Windows 上本地终端无输出/挂死。
- **根因**：该 Insider 内核构建上 `CreatePseudoConsole` 启动的进程输出未真正接管到伪控制台（子进程横幅直接打到服务器控制台，PC 输出管无数据）。
- **修复**：`terminal.go` 抽象平台无关 `localShell`（read/write/resize/kill/wait/close）；`terminal_windows.go` 实现 ConPTY 优先 + **4 秒输出校验**（超时无输出判定失效，`TerminateProcess` 后回退普通管道，shell 自行整行回显，服务端 `\r→\n` 归一）；`conptyBroken` 原子量记忆失效状态避免重复白等；`terminal_unix.go` 提供 Linux/macOS creack/pty 实现（bash/sh/zsh/fish 白名单 + `$SHELL` 默认）。
- **验证**：WS 无头探针收到完整 cmd 横幅与命令回显；浏览器内终端键入执行正常。✅（见 §4 BUG#8 同链路）

### BUG#6 功能开关切换不响应（桌面/Dock/开始菜单不增删）
- **现象**：管理端关闭某应用功能后，用户桌面图标不消失，重开浏览器才生效。
- **修复**：`appstate.ts` `set()` 原地改属性 `this.enabled[key] = on` → 整体替换对象 `this.enabled = { ...this.enabled, [key]: on }`（入口列表以引用比较驱动响应式增删）。
- **验证**：关闭「终端」→ 桌面图标/开始菜单条目即时消失；重新打开即时恢复。✅

### BUG#7 Office 编辑器多文档窗口内容串位
- **现象**：连开两个 xlsx，第二个窗口标题是新文件名，但预览/编辑仍是第一个文件的内容；保存会写到错误的文件。
- **根因**：`windows.ts` 单实例复用策略未排除 officeeditor，且 OfficeEditor 组件对 props 变更无监听。
- **修复**：officeeditor 加入多开白名单（与 explorer/notepad/imageviewer/mediaviewer 同级，每文档一窗口）。
- **验证**：同时打开两个不同 xlsx → 两个窗口各自渲染各自文件内容，分别编辑保存互不串扰。✅

### BUG#8 终端并发槽位泄漏 → 429「并发终端数已达上限」
- **现象**：开过若干次终端后，新连接/重连返回 429；重启服务才恢复。
- **根因**（goroutine dump 定位）：父进程启动 shell 后**未关闭子进程侧的管端副本**（ConPTY 路径的 `inR/outW`、管道路径的 `inR/outW`）。子进程退出后父进程仍握着输出管写端 → `outR` 永远收不到 EOF → 输出 goroutine 永久阻塞在 `Read` → `runLocal` 卡死在 `<-quit`（terminal.go:306）→ WS 处理器不返回 → `defer termRelease` 不执行 → 槽位只增不减，撞 `maxLocalPerUser=4` 即 429。
- **修复**（四处）：
  1. `terminal_windows.go` ConPTY：`CreatePseudoConsole` 成功后立即 `CloseHandle(inR); CloseHandle(outW)`（PC 内部持有自己的句柄引用，与 Windows Terminal conpty.c 同款做法）；
  2. `terminal_windows.go` 管道：`cmd.Start()` 成功后立即 `inR.Close(); outW.Close()`；
  3. 两处 cleanup/close 只关父进程实际持有的端（`!= 0` 判空，避免重复关闭）；
  4. 前端配套：`TermPanel.vue` 会话参数变化/重连前先置 `manualClose = true`（旧 ws 的异步 onclose 不再把新会话状态覆盖成「连接已断开」）；`Terminal.vue` 本地模式等 `platform` 接口返回 defaultShell 后再挂面板（消除空 shell 双握手，避免白占一个并发槽位）。
  5. 保留 `[term] DENY` 日志（429 时记录撞的是全局限额还是用户限额），移除排查期的 ACQUIRE/RELEASE 噪音日志与 `/api/debug/termstack` 诊断端点。
- **验证**：
  - 无头 WS 探针：连续开/关 **5 个**本地终端会话（上限 4），修复前第 5 个必 429 —— 修复后 **5/5 成功**，每会话均收到 hello + 命令回显；
  - 浏览器：开终端 → 键入 `echo HELLO_BUG8_OK` 执行并渲染输出 → 点「关闭终端」→ 重新打开 → 新会话正常出横幅与提示符，全程无 429、无「连接已断开」残留（截图 t12/t13）。✅

## 7. 已知限制（非缺陷，记录备查）
1. **Windows 管道回显模式下 cmd 横幅中文乱码**（`版本`→`汾`）：cmd 在管道下以 GBK(936) 输出、xterm 按 UTF-8 解码，仅影响开发机 Windows 的欢迎横幅首屏；英文命令与输入输出不受影响。**对 Linux 目标部署无影响**（bash + PTY + UTF-8）。
2. **OnlyOffice 未配置**：站点设置 `onlyoffice_url` 为空时 Office 走内置静态预览（SheetJS/docx-preview/iframe pdf），属设计行为；配置 URL 后自动切换协作编辑。
3. **IAB 自动化输入特性**：内置浏览器 `tab.type` 走 insertText 不产生 keydown（xterm 不响应），驱动 xterm 需合成 `KeyboardEvent` 且**必须带正确的 legacy keyCode**（可打印键 = 大写字母码，Enter=13；误用字符小写码 120 会被 xterm 映射成 F9 序列）——属测试工具限制，真实用户键盘输入不受影响。

## 11. 2026-09-18 加测：本地盘用量显示错误（删除后仍显示占用）

**现象**：管理员在 D 盘上传文件后删除并清空回收站，「此电脑」中 D 盘仍显示占用 790MB（实际目录为空，usage_bytes=828513559 陈旧值）。

**根因（两个叠加）**：
1. `Policies()`（fs.go）懒重算用量时用 `DriverFor(&p, x.user)` —— 本地策略驱动根是**当前查看者的隔离目录**，却写进**策略级** `usage_bytes`：多人共用一盘时显示值随"最后访问者"漂移（last-viewer-wins）。
2. 重算有 10 分钟缓存（`usage_at`），文件删除后最长 10 分钟内显示陈旧值——用户删除 790MB 文件时正好命中：打开此电脑（重算=790MB）→ 删除 → 缓存窗口内不重算 → 一直显示 790MB。

**修复**：
1. 重算改为按**策略根**（全部用户隔离目录）汇总整盘真实用量（`DriverFor(&p, nil)`）。
2. 新增 `touchPolicyUsage(ids...)` 在文件变更处即时清除用量缓存（`usage_at=NULL`，下次请求即重算）：删除、回收站恢复、同盘复制、跨盘复制、跨盘移动（源+目标）、文本保存、秒传落盘、上传合并完成、压缩、解压。清空回收站不改盘根故不触发。

**验证（2026-09-18，管理员账号 API 实测）**：
| 步骤 | 结果 |
|------|------|
| 重启后查 D 盘用量 | ✅ 828513559 → **0**（整盘重算，目录为空） |
| 写 100KB 文件到 D，立即查 | ✅ 102400（即时失效生效，无 10 分钟延迟） |
| 删除该文件，立即查 | ✅ **0** |

## 13. 2026-09-18 加测：整盘共享 / 访客共享可见 / 图标权限竞态 / 传输收尾体验

**需求（用户反馈 6 项）**：① 管理员要能共享整个分区；② 共享给"访客"或"所有人"的文件夹，访客在共享里都看不到；③ 传输面板错误行提示"重试"却没有重试按钮；④ 多文件夹批量上传全部完成时没有完成通知；⑤ 全部上传完成后面板头部仍显示上传速度；⑥ 访客刷新桌面时瞬间闪现管理员可见的图标。

**根因**：
1. **整盘共享**：`usershare.go Create()` 显式拒绝 `path == "/"`（"请选择要共享的文件夹"）。
2. **访客看不到共享**：消费端点（`with-me`/`info`/`list`/`raw`/`download`）全部挂了 `middleware.AppGate("usershare")`——被共享者本人的"内部共享"权限把**被共享的内容**也挡掉了。访客组 usershare=false → 403 → 前端 catch 成空列表。另外 `userShareFull()` 对 `sh.Path == "/"` 的前缀校验 `HasPrefix(full, "//")` 恒假，整盘共享即使建出来也会全部"路径越界"。
3. **无重试按钮**：`transfer.retry()` 已存在但面板未暴露入口。
4. **无完成通知**：任务到终态后无任何汇总提示。
5. **速度残留**：衰减器半衰（×0.5）无限趋近 0 但不等于 0，头部 `↑速度` 永远停不掉；且错误路径不清零 `t.speed`，被 `totalSpeed` 继续累加。
6. **图标闪现**：`appstate` 的 `isAvailable` 在 `/api/apps` 返回前对**所有** key 返回 true（原注释"未加载前一律视为启用，避免入口闪烁"）——桌面先按全功能渲染，权限清单到位后才收敛，中间窗口访客看到无权限图标。

**修复**：
1. `usershare.go`：`Create()` 允许 `path == "/"`，展示名用策略名+盘符（如「本地磁盘 (D:)」）；`userShareFull()` 对根共享单独处理（Clean 已拒绝 `..` 穿越，任何规整绝对路径都在根内）。
2. 消费端点去掉个人 `AppGate`，改由 handler 内 `shareFeatureOn()` 仅校验**全局**功能开关：被共享者能否看到取决于共享目标（用户/组/所有人）命中，发起/管理（create/mine/cancel）与共享内写操作仍挂个人门控（安全红线不变）。
3. 前端：「此电脑」磁盘右键菜单新增「共享整个磁盘…」（`canShareUser` 门控，访客不可见）；共享对话框支持根路径（`usPolicy` 独立记录所属策略）。
4. `TransferPanel.vue`：错误行新增 ↻ 重试按钮（复用断点续传，不从头传）。
5. `transfer.ts`：`run()` 失败时清零速度；衰减器 1.5s 无字节**直接归零**；`allSettled()` 在泵收尾时检查队列是否清空，发"全部上传完成：N 成功"或"上传结束：N 成功，M 失败（失败项可点重试）"通知；面板头部新增「N 进行中」，速度仅在确有活动任务时显示。
6. `appstate.ts`：`isOn/isAllowed/isAvailable` 未加载完成前一律 **false**（宁可图标晚 100ms 出现，也不闪无权限图标）；`load()` 重拉前先回落到未决（消除登录/切账号后两次响应之间的窗口）；拉取失败标记已决并回退默认全允许（离线兜底）；`useDesktopIcons` watch 增加 `loaded` 翻转补同步。
7. **顺手发现并修复（存量 bug）**：用户配额记账 `gorm.Expr("MAX(used_bytes ± ?, 0)")` 在 MySQL 下是**语法错误**（MAX 是单参聚合函数，逐行取大应使用 `GREATEST`）——每次上传/清空的配额增减全部静默失败（日志 Error 1064）。`fs.go`/`tasks.go` 共 7 处统一改为 `GREATEST`。

## 14. 2026-09-18 加测：海报资源库(T:) 对访客/普通用户隐藏 + 管理台「共享审计」

**需求（用户反馈 2 项）**：① 海报资源库（T: 内置只读盘）访客和普通用户不能看到；② 有分享审计（外链分享）却没有共享审计（站内共享）——分享=创建链接给外部下载，共享=直接授权给指定用户/用户组随时可见，两者是不同功能，要分开审计。要求先弄清功能逻辑，发现 BUG 就修复。

**功能逻辑梳理**：
- **分享（外链，`shares` 表）**：`POST /api/shares` 生成 token 链接，任何人凭链接（+提取码）可浏览/下载，管理员在「分享审计」查看；有 Views/Downloads 计数。
- **共享（站内，`user_shares` 表）**：`POST /api/usershares` 把某目录授权给 指定用户 / 用户组 / 所有人，目标账号登录后在资源管理器「共享」区直接可见、随时下载，无需链接。消费端点不挂被共享者个人权限（否则共享给访客永远不可见，见 §13），只受全局功能开关约束。
- **T: 海报资源库**：`type=builtin` 只读盘（内容 embed 进二进制，物化到 `data/builtin/poster`），是「海报设计」应用的模板/素材来源——应用内 iframe 经 `/api/fs/raw?policyId=T` 读取。

**根因（T 盘为什么所有人都看得到）**：`Policies()` 列表与 `fscore.Resolve()` 只按 `UserGroup.CanUsePolicy`（`allowed_policy_ids` 空=全部可见）过滤——两个组的该字段都为空 → T 盘进入**每个用户**（含访客）的资源管理器盘列表，且任何用户都能直接 `fs/list`、`fs/raw` 读 T 的全部内容。

**修复（代码已实现并部署）**：
1. **列表层隐藏**：`fs.go Policies()` 对非管理员跳过 `type=builtin`——T 盘不再出现在访客/普通用户的盘列表（管理员保留）。
2. **API 层门控**：`fscore/service.go Resolve()` 增加——非管理员访问 builtin 盘必须持有「海报」功能权限（`model.AppAllowed("poster", u)`），否则 403「该存储仅管理员可用」。访客组 poster=false → 彻底读不到 T；普通用户组 poster 默认开 → 海报应用可用但 T 不作为普通盘暴露。
3. **泄漏守卫（本轮新发现的 BUG，已修复）**：仅做 1+2 后，持有海报权限的普通用户仍可对 T **发起**三种外流通道（ReadOnly 驱动挡的是写，挡不住"授权别人读"）：
   - 外链分享 `share.go Create` → 增加 `builtin && 非管理员 → 403 内置资源库不能分享`；
   - 站内共享 `usershare.go Create` → 403 内置资源库不能共享；
   - 免登录直链 `dlink.go Create`（可签永久链，最危险）→ 403 内置资源库不能生成直链。
   管理员不受限（T 本就是他建的）；管理员若把 T 目录共享给他人，消费端走 `DriverFor(创建者)` 不复查被共享者权限，不受影响。
4. **海报应用解耦**：T 盘不进盘列表后，应用改走专属接口 `GET /api/poster/builtin/policy`（挂 AppGate("poster")）取 policyId，其余读写仍走通用 fs 只读接口；`Poster.vue` 的 `tPolicy` 由"从盘列表找 builtin"改为"列表找→找不到调专属接口"。

## 16. 2026-09-18 加测：访客幽灵配额修复 + 属主记账 + 启动配额对账

**需求（用户反馈）**："访客我访问，发现 C D E 盘占用了几百 MB，但是我都没找到占用的文件。"

**根因（3 个，均已在生产数据上证实）**：
1. **历史记账泄漏**：`used_bytes` 是增量式记账（上传+、清空回收站-）。修复 MAX() 报错之前的旧版本里，清空回收站的扣减 SQL（`MAX(used_bytes-?,0)`）执行时静默报 1064 失败——t14 上传测试给访客加了 975,177,743 字节（900MB+30MB+2063B，与测试文件严丝合缝），清理时扣减全部失败，留下永久幽灵；系统没有任何对账通道能修正它。
2. **回收站退款记错人**：`RecycleItem.UserID` 只存删除者。管理员代删访客文件后清空回收站，退款扣的是管理员（被 GREATEST 钳在 0），访客的占用永远退不掉——与第 1 条同构的永久幽灵。
3. **`AdminLocalDriver` 漏改的裸类型断言**（§15 的包装驱动引入）：`PhysicalOf` 硬断言 `*LocalDriver` → 管理员在用户目录内删除/恢复/上传全报"非本地存储/仅本地存储"；`upload/complete` 还有一处独立断言 → 管理员**任何分块上传**都报"该存储类型暂不支持分块上传"；Rename/Move/版本恢复共 4 处同病（版本历史不跟随迁移、版本恢复被拒）。

**修复（代码已实现并部署）**：
1. **启动配额对账**（`handler/tasks.go reconcileQuotas`，每次启动、先于各清扫执行）：按盘上实测重算每个用户 `used_bytes` = 各活跃本地策略下用户目录文件总大小（`.versions` 版本历史与 `.assembling` 合并临时文件不计——两者从未参与配额记账，口径一致）+ 回收站内未清空文件实测大小（删除不退款、清空才退款，故回收站内仍计配额）。有漂移即校正并写日志 `[quota] 启动对账校正`。存在活跃云盘策略时整体跳过（云盘侧用量无法本地遍历）。**历史与新产生的任何记账偏差都会在下次重启自动归零。**
2. **属主记账**：`RecycleItem` 新增 `OwnerID`（0=历史记录回退删除者）；本地盘删除时按物理路径一级目录定位属主（`fscore.OwnerOfPhys`）；清空回收站/超期清扫的退款一律退给属主。上传落盘配额同样按属主计（`commitQuotaCore` 支持 owner 参数，`quotaAccountOwner` 按落盘目录定位）——管理员经管理视图写入他人目录时计入属主配额，属主超限则拒绝并通知属主。
3. **包装驱动补全**：`PhysicalOf` 按 `AdminLocalDriver.route(vp)` 落到具体物理根；新增 `fscore.LocalRoot(d, vp)` 替换全部 4 处裸 `*LocalDriver` 断言（分块上传完成、Rename 版本迁移、Move 覆盖归档+版本迁移【跨根移动不迁移版本，保持历史行为】、版本恢复）；`AdminLocalDriver` 新增 `RouteFor` 导出路由。

- **壁纸同源代理（本轮新增，修复 C: 顶层 CSP 拦截外部壁纸图的缺陷）**：
  - 端点 `GET /api/fs/wallpaper?p=<base64url(url)>&t=<token>`（`handler/wallpaper.go`）；CSS 变量改指向同源代理，顶层 CSP `img-src 'self' data: blob:` **保持不变**（若放宽 https: 通配，恶意 .md/office 文件的 `<img>` 将成像素外传通道）。
  - 端点安全：SSRF 段检查（环回/私网/链路本地/CGNAT/IETF 保留全拒）+ 重定向逐跳复检 + 仅回传 `image/*` + 20MB 上限。
  - curl 实测：127.0.0.1 / 10.255.0.1 / 192.168.1.1 / 169.254.169.254 / 100.64.0.1 / metadata.google.internal 全部 400 拒绝；HTML 内容 502；真实图片 200 + image/png。
  - UI 实测：应用壁纸后 CSS 变量指向 `/api/fs/wallpaper?p=…`，页面内 fetch 该代理返回 `200 image/jpeg 252KB`，**顶层+所有 iframe 控制台零错误**（此前为 img-src CSP 违规）。
  - 顺带修复存量缺陷：壁纸中心「我的壁纸（URL）」缩略图与壁纸渲染同样经代理，此前被 CSP 拦截不可用。
